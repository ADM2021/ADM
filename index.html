I

The AAA Framework

Access control systems are built on three core pillars (AAA) along with the initial step of identification to securely manage network security:

Identification

The process where a subject claims a specific identity on a system (e.g., entering a username, scanning an NFC badge).

Authentication

Verifying the claimed identity using credentials such as passwords, PINs, smart cards, tokens, or biometric attributes.

Authorization

Determining which specific resources, operations, or data folders the authenticated identity is permitted to access based on policies.

Accounting

Logging user events, connections, data usage, and session times to maintain a detailed audit trail for compliance and forensic investigations.

Centralized AAA Servers (e.g., RADIUS, TACACS+)

Instead of maintaining user databases on every network device (like VPN concentrators or switches), a centralized AAA server acts as a single source of truth. When a user authenticates via a VPN, the VPN concentrator acts as a middleman, forwarding credentials to the central AAA server which evaluates the request and returns an accept or reject response.

II

Security Controls & Matrix

Security controls are categorized by their implementation method (Technical, Managerial, Operational, Physical) and function (Preventive, Detective, Corrective, Compensating, Deterrent, Directive).

Control Category Definition Examples
Technical Controls implemented through hardware, software, or OS configurations. Firewalls, Antivirus, Encryption, IPS/IDS.
Managerial Controls implemented through administrative policies, guidelines, and procedures. Security Policies, Risk Assessments, Onboarding checks.
Operational Controls implemented through human execution and organizational processes. Security guards, User training, Lunch & Learn events.
Physical Tangible, real-world controls that restrict physical access to hardware and properties. Fences, door locks, CCTV cameras, server cages.
Preventive

Actively blocks unauthorized activity (e.g., firewall rules, security guards checking IDs).

Deterrent

Discourages potential attackers from attempting breaches (e.g., warning banners, warning signs).

Detective

Identifies and records incidents after or during occurrence (e.g., audit logs, motion sensors, CCTV).

Corrective

Reverses impacts and restores operations post-incident (e.g., database backups restoration, system patches).

Compensating

Temporary, alternative measures put in place when primary controls are unavailable (e.g., custom firewall filters).

Directive

Rules or signs designed to guide behavior (e.g., "Authorized Personnel Only" signs, security policies).

III

Change Management Procedures

Technical change management is critical in corporate networks to prevent service downtime, ensure security, and maintain stability. Bypassing these procedures can result in catastrophic operational failures.

1
Proposal & Scope Document

Technicians must document the precise scope and technical reasons for a proposed change before any actions are scheduled.

2
Risk Analysis & Timing Evaluation

The Change Control Board (CCB) analyzes the risks of making the change vs. NOT making the change (e.g., remaining vulnerable). They also schedule updates during off-peak times or implement "change freezes" (e.g. holiday retail freeze).

3
Sandbox Testing & Rollback Preparation

Changes are tested in a non-production "sandbox". Technicians formulate a backout plan (contingency steps to revert the system) and take a full backup immediately prior to implementation.

4
Validation & Recovery

Following execution, the system owner validates that all services run as expected. If failures occur, the rollback plan is initiated to restore the stable baseline state.

IV

Deception Technologies

Security teams deploy simulated assets to distract, slow down, and analyze malicious actors, while triggering high-fidelity alerts on unauthorized access.

Honeypots

Decoy systems designed to look like production servers, which attract and isolate attackers to study their techniques.

Honeynets

A complete mock network infrastructure consisting of virtualized firewalls, routers, and decoy servers to study network attacks.

Honeyfiles

Attractive, decoy files (such as "passwords.txt") that trigger immediate silent alerts the moment they are opened or accessed.

Honeytokens

Traceable, fake pieces of data (e.g., mock email addresses, database rows, API credentials) used to identify data leaks and track distribution.

V

The CIA Triad & Gap Analysis

The foundational framework of information security consists of three core components, often evaluated against target standards using gap analysis models:

🕵️ Confidentiality

Ensuring that only authorized users can access sensitive data (achieved via encryption, masking, access control lists).

🛡️ Integrity

Ensuring that data remains complete, accurate, and unaltered (achieved via hashing, digital signatures, version controls).

🔋 Availability

Ensuring systems and data are accessible when needed (achieved via fault tolerance, redundancy, backups, and patching).

Gap Analysis Reports

A gap analysis compares an organization's current security posture against a desired standard or baseline (such as NIST SP 800-171 or ISO 27001). I

Cryptographic Foundations: Hashing & Digital Signatures

Hashing

A cryptographic hash is a "digital fingerprint" or message digest that represents data as a short, fixed-length string of text. Hashing is a one-way process; the original data cannot be recreated from the hash.

Core Purpose
Integrity

Verifies that data has not been altered. Even a single character change (e.g., changing a period to an exclamation mark) results in a drastically different hash (the avalanche effect).

Popular Algorithms
SHA-256 vs MD5
  • SHA256: Produces 256 bits of information, represented as 64 hexadecimal characters. Common standard.
  • MD5: Older algorithm, no longer recommended due to collisions (vulnerabilities where different inputs yield matching hashes).
Practical Applications
File Verification

Comparing a downloaded file's hash to the one posted on the source website to confirm it was not tampered with.

Password Storage

Storing password hashes instead of plaintext in databases. A compromised database does not reveal original passwords directly.

Salting

Adding unique, random data to a password before hashing to neutralize rainbow table attacks (pre-compiled hash lists).

Digital Signatures

Digital signatures provide three key security benefits: Authentication, Non-repudiation, and Integrity.

How It Works (Process Flow)
  1. The sender hashes the plaintext document.
  2. The sender encrypts this hash using their own private key. This encrypted hash is the digital signature.
  3. The receiver decrypts the signature using the sender's public key to retrieve the hash.
  4. The receiver calculates a local hash of the received document and compares it to the decrypted hash.
  5. If the hashes match, the document's authenticity and integrity are verified, and the sender cannot deny sending it.
II

Encryption Technologies & Key Management

Encryption States
Data at Rest

Protected using full disk encryption like BitLocker (Windows) or FileVault (macOS), or file-level encryption like EFS (Windows).

Data in Transit

Secured using HTTPS (SSL/TLS) for web traffic or VPNs. Site-to-site VPNs often use IPsec, while client-based VPNs use SSL/TLS.

Database Encryption
  • Transparent Encryption: Uses a symmetric key to encrypt the entire database file on disk.
  • Column-level Encryption: Encrypts specific sensitive fields (e.g., SSN, credit cards) to minimize processing overhead.
Algorithms & Keys

Encryption relies on public, well-known algorithms (like AES or DES), while security is maintained strictly through the secrecy of the key.

Symmetric vs Asymmetric
  • Symmetric: Single shared key for both encryption and decryption. Fast, but hard to distribute securely at scale.
  • Asymmetric: Public/private key pair. Public key encrypts, private key decrypts. Scales easily, but slower.
Key Exchange Methods
  • Out-of-band: Exchanging keys via an external, non-network medium (e.g., phone, courier).
  • In-band: Exchanging keys over the network, using asymmetric encryption to protect a session key.
  • Key Exchange Algorithms: Dynamically building matching symmetric keys on both sides without sending the key itself.
Key Stretching

Hashing or encrypting a key multiple times (e.g., PBKDF2 or bcrypt) to slow down brute-force attacks.

III

Public Key Infrastructure (PKI) & Certificates

PKI encompasses the policies, hardware, software, and procedures used to manage, distribute, and revoke digital certificates.

Digital Certificates
  • Standard Format: X.509 is the global standard format for digital certificates.
  • Certificate Authority (CA): A trusted third party that validates identities and cryptographically signs certificates.
  • CSR (Certificate Signing Request): The initial file created by an applicant (containing their public key and identification details) sent to a CA to request a signed certificate.
  • Wildcard Certificates: Uses an asterisk (e.g., *.domain.com) to secure a main domain and all its subdomains.
Trust Models & Revocation
  • Root of Trust: An inherently trusted anchor (software, hardware, or firmware) used to validate other elements in the trust chain.
  • Web of Trust: An alternative decentralized model where individuals sign each other's certificates.
  • CRL (Certificate Revocation List): A list of revoked certificates maintained by the CA. Browsers download this file periodically.
  • OCSP (Online Certificate Status Protocol): A real-time protocol allowing browsers to query the CA about a single certificate's status.
  • OCSP Stapling: The web server "staples" a time-stamped, CA-signed OCSP response directly into the SSL handshake, reducing traffic to the CA.

Hardware Type Core Function Key Use Case
TPM (Trusted Platform Module) A dedicated security chip embedded on a motherboard providing local cryptographic operations. Full-disk encryption (e.g., Windows BitLocker), secure boot validations, and secure local key storage.
HSM (Hardware Security Module) A high-performance physical device or plug-in card for large-scale enterprise cryptography. Managing, storing, and generating keys for thousands of SSL web servers in an enterprise datacenter; offers high-availability.
Secure Enclave A dedicated co-processor built directly into modern CPU architectures, isolated from the main processor. Managing the device boot ROM, real-time memory encryption, and hardware-based AES on mobile devices (e.g. Apple FaceID/TouchID).

Executive Summary

Modern cybersecurity threats are characterized by a diverse array of attack vectors ranging from sophisticated technical exploits to psychological manipulation. Attackers leverage vulnerabilities in memory management (buffer overflows, DLL injections), software development (race conditions), and the human element (social engineering and impersonation). Critical risks emerge from unpatched operating systems, compromised supply chains—as seen in the SolarWinds incident—and the physical bypass of digital security via USB devices. Mitigation requires a "defense in depth" strategy, involving rigorous patch management, digital signature verification, robust backups, and employee awareness to counter evolving threat vectors.

I

Technical Memory and Software Exploits

Attackers frequently target the way applications manage data within system memory to alter intended functioning:

Buffer Overflows

Occurs when an application writes more data to a block of memory (buffer) than it is allocated to hold. The extra data spills over, overwriting adjacent memory spaces. This can corrupt data, crash the application, or allow attackers to overwrite the instruction pointer to execute arbitrary code.

DLL Injection

A technique where attackers force a running process to load a malicious Dynamic Link Library (DLL). Once loaded, the malicious code executes within the security context of the target process, allowing the attacker to bypass access controls and run unauthorized commands.

Race Conditions (TOCTOU)

A vulnerability arising in multi-threaded software when the system's security posture depends on the sequence or timing of processes. In Time-of-Check to Time-of-Use (TOCTOU) exploits, attackers modify a resource in the brief interval between its validation and its actual utilization.

II

Social Engineering and Human Vulnerabilities

The human element remains one of the most exploited aspects of cybersecurity, bypassing traditional network perimeters:

Impersonation & Social Engineering

Attackers use psychological manipulation to trick individuals into revealing sensitive information or granting access. This includes impersonating IT support, executives (business email compromise), or service providers to build trust.

Smishing & Vishing

Phishing variants targeting mobile communication. Smishing uses SMS text messages, and vishing uses voice calls (often spoofed) to manipulate victims into disclosing credentials, financial info, or installing malware.

Watering Hole Attacks

An attacker identifies websites frequently visited by a specific target group (e.g., defense contractors) and infects one of those sites. When the target group visits, their systems are compromised, bypassing external perimeter defenses.

III

Supply Chain and Hardware Threats

Physical devices and external dependencies present significant vectors for intrusion:

USB Rubber Ducky

A malicious USB device that registers as a standard USB keyboard. Because OSs inherently trust keyboard inputs, the device can rapidly inject keystrokes to execute commands, download malware, or exfiltrate data, bypassing firewalls.

Supply Chain Vulnerabilities

Attackers target weaker links in an organization's supply network. By compromising a trusted vendor, the attacker introduces vulnerabilities into products (updates or hardware) that are later installed by the target organization.

SolarWinds Incident

A landmark supply chain attack where state-sponsored attackers compromised SolarWinds' Orion build system, injecting a backdoor (SUNBURST) into updates distributed to thousands of customers, including government agencies.

IV

Software Development and Infrastructure Defense

Securing software and infrastructure requires active defense and validation strategies:

Dynamic vs. Static Analysis

Static analysis (SAST) examines source code or binaries without executing them to find errors/vulnerabilities. Dynamic analysis (DAST) tests the application during execution, injecting inputs to observe real-time behavior and memory leaks.

Defense in Depth

A cybersecurity strategy employing multiple layers of security controls throughout an IT system. If one defense layer fails (e.g., firewall), other layers (endpoint detection, encryption, access controls) protect critical assets.

Patch Management & Digital Signatures

Keeping software updated closes known vulnerabilities. Digital signatures verify the authenticity and integrity of software updates, ensuring they originate from a trusted publisher and haven't been modified.

I

Malware Varieties & Characteristics

Malicious software (malware) represents a wide variety of tools designed to compromise system integrity, steal data, or restrict access:

Worms vs. Viruses

A computer worm propagates itself automatically across network systems by exploiting vulnerabilities without needing human interaction. Traditional viruses require human action (such as running an infected file) to replicate and spread.

Trojans & Ransomware

Trojans disguise themselves as legitimate software while carrying a malicious payload in the background. Ransomware encrypts user data but leaves the OS running to display ransom notes. Backups must be offline to prevent their encryption.

Rootkits & Logic Bombs

Rootkits grant administrative access while hiding themselves from detection tools by modifying OS components. Logic bombs remain dormant inside software until a specific trigger condition (e.g., date or event) fires their execution.

II

Application & Web Vulnerabilities

Insecure coding and configuration practices expose applications to remote exploitation:

SQL Injection (SQLi)

Code injection that allows attackers to manipulate backend database queries. Injecting a tautology like "1=1" forces the database to evaluate the query as true for all records, returning sensitive tables without authentication.

Cross-Site Scripting (XSS)

Exploits the client browser's trust in a website to run malicious scripts. Non-persistent (reflected) XSS is passed via client links and reflected off the server; persistent (stored) XSS is stored on a database and run by anyone visiting the page.

Memory & Path Exploits

Directory Traversal manipulates web path directories to access files outside the web root. Out-of-bounds writes modify memory outside designated buffers (enabling RCE). Remote Code Execution (RCE) lets attackers run arbitrary commands.

III

Infrastructure & Device Exploits

Device configurations and virtualization structures require strong controls to prevent lateral movement and isolation escape:

Default Credentials & IoT

Pre-configured passwords (e.g., admin/12345) left on IoT devices allow automated scanners like the Mirai botnet to log in, compromise systems globally, and organize them into distributed attack networks (DDoS).

Mobile Sideloading & OS Modding

Jailbreaking (iOS) and rooting (Android) replace secure vendor firmware with unvetted versions. This circumvents Mobile Device Management (MDM) security restrictions and permits "sideloading" of potentially insecure apps.

VM Escape & Resource Reuse

VM escape allows an attacker to break out of guest VMs to access the host hypervisor or other guest VMs. Resource reuse occurs when a hypervisor reassigns memory/storage to a new VM without sanitizing or clearing legacy data.

IV

Supply Chain, Zero-Days, & Management

Managing external dependencies and unpatched vulnerabilities is key to maintaining a strong organizational security posture:

Supply Chain Integrity

Attackers target third-party service providers or build pipelines. The 2013 Target breach utilized a compromised HVAC vendor. The SolarWinds attack compromised the build server to inject a backdoor (SUNBURST) into signed updates.

Zero-Days & CVE/CVSS

Zero-days are exploits targeting unknown, unpatched vulnerabilities. Cybersecurity professionals reference the public CVE database to track software vulnerabilities and use the CVSS scale (0-10) to rank severity levels.

Asset Lifecycle (EOL/EOSL)

End of Life (EOL) signals the stop of sales; End of Service Life (EOSL) means the vendor stops security updates, leaving systems exposed. Unreplaceable legacy systems must be isolated via strict firewall and IPS rules.

Practice Quiz

What is a "drive-by download" and how does it occur?
Answer Key: Definition: Automatic download of malware without user interaction. Occurrence: Visiting a malicious site that exploits known vulnerabilities.

Detailed Explanation: A drive-by download refers to the automatic download of malicious information or software onto a system without the user clicking on any specific links or buttons. This typically occurs when a user visits a malicious website or location that takes advantage of a known vulnerability to propagate a worm or install malware.
Explain the primary difference between a non-persistent (reflected) XSS attack and a persistent (stored) XSS attack.
Answer Key: Non-persistent: Script is sent to a specific user (e.g., via link) and reflected off a site. Persistent: Script is stored on a server (e.g., social media) and affects all visitors.

Detailed Explanation: A non-persistent XSS attack involves an attacker sending a malicious script to a victim, often via an email or search query, which is then executed by the user’s browser against a third-party website. In contrast, a persistent XSS attack involves the attacker storing the malicious payload directly on a server—such as a social media site—so that it is automatically executed by the browser of anyone who visits the infected page.
Why is it considered a best practice to store data backups offline?
Answer Key: Prevention: Disconnecting backups ensures ransomware cannot reach or encrypt them. Recovery: Allows for a clean restoration after wiping an infected system.

Detailed Explanation: Storing backups offline prevents ransomware from identifying and encrypting the backup files during an infection. If the backup is disconnected from the network, an attacker cannot access or lock the data, allowing the user to delete the infected system and restore their files from a known good, clean copy.
What is the significance of the statement "1=1" in the context of a SQL injection attack?
Answer Key: Condition: "1=1" is a tautology (always true). Outcome: It forces the database to validate the query as true for all rows, granting unauthorized access to all data in the database.

Detailed Explanation: In SQL injection, "1=1" is a condition that is always true, which attackers append to database queries to circumvent security checks. By injecting this code into an input field, an attacker can trick the database into returning all records in a table rather than filtering for a specific, authorized result.
How did the Target Corporation breach of 2013 demonstrate a supply chain vulnerability?
Answer Key: Entry Point: An HVAC vendor (third-party service provider). Vulnerability: Lack of network segmentation between the HVAC systems and the payment network (cash registers).

Detailed Explanation: The breach began when attackers infected a third-party HVAC vendor with malware via email to gain access to their systems. Because the HVAC vendor had remote access to Target’s network, and because the HVAC systems were on the same network as the cash registers, the attackers were able to move laterally and steal 40 million credit card numbers.
Define "VM escape" and explain the risk it poses to a virtualized environment?
Answer Key: Definition: Jumping from one VM to another via the hypervisor. Risk: Compromises the isolation of virtual environments, exposing data from all systems on that host.

Detailed Explanation: VM escape is an exploit where an attacker gains access to one virtual machine (VM) and manages to jump across the hypervisor to access other VMs or the host system. This is a severe security risk because a single hypervisor may manage hundreds of VMs, potentially giving an attacker simultaneous access to a vast amount of sensitive data across multiple isolated systems.
What is the difference between "End of Life" (EOL) and "End of Service Life" (EOSL)"?
Answer Key: EOL: Product is no longer sold, but may still receive updates. EOSL: All support and security patching have ceased.

Detailed Explanation: End of Life (EOL) is a manufacturer’s notice that they will soon stop selling a particular product, though security patches may still be available for a limited time. End of Service Life (EOSL) indicates that the manufacturer has officially stopped all support, including security updates, making the device a significant risk if it remains on the network.
How do jailbreaking and rooting impact the security of a mobile device?
Answer Key: Impact: Replaces the secure OS with one that provides unrestricted access. Consequence: Bypasses MDM security policies and enables the "sideloading" of unauthorized, potentially malicious apps.

Detailed Explanation: Jailbreaking (on iOS) and rooting (on Android) involve replacing the device's original firmware or operating system with a third-party version to gain elevated access. This process circumvents built-in security restrictions and management controls, such as a Mobile Device Manager (MDM), potentially allowing for the installation of malicious unauthorized applications.
Describe the risk associated with default credentials and how they are exploited by botnets like Mirai.
Answer Key: Risk: Known passwords (e.g., "admin/admin") are easily guessed. Exploitation: Botnets like Mirai use automated lists to compromise thousands of IoT devices globally.

Detailed Explanation: Many Internet of Things (IoT) devices are shipped with standard usernames and passwords that users often fail to change. The Mirai botnet uses a list of over 60 of these default configurations to automatically scan the internet, gain access to vulnerable devices like cameras and routers, and incorporate them into a larger botnet for the attacker's use.
What constitutes a "zero-day attack"?
Answer Key: Definition: An exploit of an unknown, unpatched vulnerability. Duration: The vulnerability remains active until the vendor discovers the issue and releases a patch.

Detailed Explanation: A zero-day attack occurs when an attacker exploits a software vulnerability that the vendor is not yet aware of and for which no patch has been created. Because the security community has "zero days" to prepare or defend against the exploit, these attacks can continue unabated until a fix is developed and deployed.

VII

Glossary of Key Terms

Acceptable Use Policy (AUP)

A set of rules and procedures within an organization defining how employees are permitted to use technology resources.

Bloatware

A category of malware or unwanted software that consumes system resources and may slow down performance.

Botnet

A network of infected systems (bots) controlled remotely by an attacker to perform coordinated tasks, such as stealing data or launching DoS attacks.

Common Vulnerabilities and Exposures (CVE)

A public database and list of known cybersecurity vulnerabilities and exposures (maintained at cve.mitre.org).

Common Vulnerability Scoring System (CVSS)

A standardized scale (0 to 10) used to rank the severity of security vulnerabilities.

Default Credentials

Standard usernames and passwords (e.g., "admin/12345") pre-configured by manufacturers on hardware like IoT devices.

Directory Traversal

A web server misconfiguration that allows users to manually move through the server's folder structure to unauthorized directories.

DoS / DDoS

Denial of Service (or Distributed Denial of Service); an attack intended to disable an application or system by overwhelming it with traffic.

Firmware

The specialized operating system running inside hardware devices (like thermostats or routers) that manages their specific functions.

Hypervisor

The software or hardware that creates and runs virtual machines, managing the relationship between physical and virtual resources.

Input Validation

A security practice where an application checks user-provided data to ensure it does not contain malicious scripts or unintended commands.

Jailbreaking / Rooting

The process of replacing a mobile device's operating system to circumvent security restrictions and gain full administrative access.

Keylogger

Malware designed to record every keystroke made on a system and send that data back to an attacker.

Logic Bomb

A type of malicious code that remains dormant until a specific event or condition triggers its execution.

Malware

A broad term describing any type of software designed to perform malicious actions on a system.

Mobile Device Manager (MDM)

A centralized system used by organizations to manage and secure mobile devices, including enforcing security policies.

Packet Capture

The process of intercepting and logging traffic as it moves across a network to inspect the data within the frames.

Remote Code Execution (RCE)

A vulnerability that allows an attacker to run any application or command of their choice on a remote system.

Resource Reuse

A virtualization vulnerability where memory or storage areas are shared between VMs, potentially allowing one VM to read data from another.

Sideloading

The installation of applications on a mobile device from sources other than official app stores (e.g., local files or company libraries).

SQL Injection (SQLi)

A code injection attack where malicious SQL statements are inserted into an entry field for execution by a database.

Trojan Horse

Malicious software that is disguised as legitimate or useful software to trick users into installing it.

Worm

A type of malware capable of automatically propagating and spreading between systems, often by exploiting known vulnerabilities.

Security+ SY0-701 Glossary

Key cryptographic terms and definitions. More terms will be added at a later date.

🔍
AAA Framework

A security framework standing for Authentication, Authorization, and Accounting used to manage access and track activity.

Accounting

The process within AAA that logs system events, including login/logout times and the amount of data sent or received.

AES (Advanced Encryption Standard)

A modern, widely-used symmetric encryption algorithm.

Asymmetric Encryption

A cryptographic method using a pair of keys: a private key known only to the owner and a public key available to anyone.

Authentication

The process of proving a claimed identity using passwords or other factors.

Authorization

The process of determining the specific resources or data a verified user is allowed to access.

Backout Plan

A documented contingency procedure used to revert a system to its original state if a change or update fails.

Baseline

A standard or goal used in gap analysis, often derived from organizations like NIST or ISO, to measure security progress.

CA (Certificate Authority)

A device or software responsible for managing and digitally signing certificates within a security infrastructure.

CIA Triad

The foundational model of IT security consisting of Confidentiality, Integrity, and Availability.

Compensating Control

A security control used temporarily to mitigate a risk when the primary control (like a software patch) is unavailable.

Corrective Control

A security control applied after an event is detected to reverse the impact or restore systems, such as a data backup.

CRL (Certificate Revocation List)

A list maintained by a CA containing certificates that are no longer valid.

CSR (Certificate Signing Request)

A request sent from an applicant to a CA to obtain a signed digital certificate.

Data Masking

A technique used to hide sensitive data by replacing it with characters like asterisks.

DES (Data Encryption Standard)

An older symmetric encryption algorithm with five steps, now largely replaced by AES.

Deterrent Control

A security control designed to discourage an attacker, such as warning signs or splash screens.

Digital Signature

A cryptographic tool that provides non-repudiation by proving both the integrity of the data and the identity of the sender.

Gap Analysis

A study comparing the current security state of an organization to a desired future state or baseline.

Hash

A short string of text representing a "fingerprint" of data; used to verify that information has not been altered (integrity).

Honeyfile

A file containing fake but attractive information used to lure and detect unauthorized users on a network.

Honeynet

A complex infrastructure of virtualized honeypots (servers, routers, firewalls) designed to look like a real production network.

Honeypot

A system designed to attract and trap attackers or automated processes to observe their techniques.

Honeytoken

Traceable, fake data (like API credentials or email addresses) used to identify the source of data leaks.

HSM (Hardware Security Module)

A centralized hardware device used for high-speed cryptographic processing and key management.

Key Stretching

A method used to strengthen weak keys by repeating the hashing or encryption process multiple times.

Managerial Control

Security controls implemented through administrative policies and procedures.

Non-repudiation

The assurance that the sender of a message cannot deny having sent it, provided by digital signatures.

OCSP (Online Certificate Status Protocol)

A real-time protocol used to check the revocation status of a digital certificate.

Operational Control

Security controls implemented through human action, such as security guards or training programs.

Perfect Forward Secrecy / Ephemeral Keys

Temporary session keys that are used for a short time and then discarded.

Performance-Based Questions

CompTIA exam questions that require the candidate to perform a task or complete a process rather than selecting a multiple-choice answer.

Physical Control

Controls that limit physical access to buildings or devices, such as locks, fences, and badge readers.

PKI (Public Key Infrastructure)

The entire system of hardware, software, and policies used to manage digital certificates.

Rainbow Table

A pre-compiled list of plaintext passwords and their corresponding hashes used to quickly crack passwords.

Salt

Random data added to a plaintext password before hashing to ensure unique hash outputs.

Sandbox

A technological "safe space" or duplicate environment used for testing changes without affecting production systems.

Stakeholders

Individuals or departments impacted by a proposed change who provide input on its timing and implementation.

Symmetric Encryption

An encryption method that uses the same key for both encryption and decryption.

Technical Control

Security controls implemented through operating systems, software, or hardware, such as firewalls.

TPM (Trusted Platform Module)

A specialized chip on a computer's motherboard that provides hardware-based security functions.

X.509

The standard format defining the information contained within a digital certificate.
