🔒 Security Architecture & Integration

A beautiful (in my humble opinion lol) design integrated with core security concepts. Attempted to display advanced security capabilities within the limitations of a static GitHub Pages environment:

Mitigates Cross-Site Scripting (XSS) and data injection attacks by strictly defining which dynamic resources are allowed to load.

Video 1 to 10 Study Guide

Core pillars of the AAA framework, security control categories, change management procedures, deception technologies, and the foundational CIA Triad.

I. AAA Framework II. Controls III. Change Mgmt IV. Deception V. CIA Triad VI. Quiz VII. Essays VIII. Glossary
I

The AAA Framework

Access control systems are built on three core pillars (AAA) along with the initial step of identification to securely manage network security:

Identification

The process where a subject claims a specific identity on a system (e.g., entering a username, scanning an NFC badge).

Authentication

Verifying the claimed identity using credentials such as passwords, PINs, smart cards, tokens, or biometric attributes.

Authorization

Determining which specific resources, operations, or data folders the authenticated identity is permitted to access based on policies.

Accounting

Logging user events, connections, data usage, and session times to maintain a detailed audit trail for compliance and forensic investigations.

Centralized AAA Servers (e.g., RADIUS, TACACS+)

Instead of maintaining user databases on every network device (like VPN concentrators or switches), a centralized AAA server acts as a single source of truth. When a user authenticates via a VPN, the VPN concentrator acts as a middleman, forwarding credentials to the central AAA server which evaluates the request and returns an accept or reject response.

II

Security Controls & Matrix

Security controls are categorized by their implementation method (Technical, Managerial, Operational, Physical) and function (Preventive, Detective, Corrective, Compensating, Deterrent, Directive).

Control Category Definition Examples
Technical Controls implemented through hardware, software, or OS configurations. Firewalls, Antivirus, Encryption, IPS/IDS.
Managerial Controls implemented through administrative policies, guidelines, and procedures. Security Policies, Risk Assessments, Onboarding checks.
Operational Controls implemented through human execution and organizational processes. Security guards, User training, Lunch & Learn events.
Physical Tangible, real-world controls that restrict physical access to hardware and properties. Fences, door locks, CCTV cameras, server cages.
Preventive

Actively blocks unauthorized activity (e.g., firewall rules, security guards checking IDs).

Deterrent

Discourages potential attackers from attempting breaches (e.g., warning banners, warning signs).

Detective

Identifies and records incidents after or during occurrence (e.g., audit logs, motion sensors, CCTV).

Corrective

Reverses impacts and restores operations post-incident (e.g., database backups restoration, system patches).

Compensating

Temporary, alternative measures put in place when primary controls are unavailable (e.g., custom firewall filters).

Directive

Rules or signs designed to guide behavior (e.g., "Authorized Personnel Only" signs, security policies).

III

Change Management Procedures

Technical change management is critical in corporate networks to prevent service downtime, ensure security, and maintain stability. Bypassing these procedures can result in catastrophic operational failures.

1
Proposal & Scope Document

Technicians must document the precise scope and technical reasons for a proposed change before any actions are scheduled.

2
Risk Analysis & Timing Evaluation

The Change Control Board (CCB) analyzes the risks of making the change vs. NOT making the change (e.g., remaining vulnerable). They also schedule updates during off-peak times or implement "change freezes" (e.g. holiday retail freeze).

3
Sandbox Testing & Rollback Preparation

Changes are tested in a non-production "sandbox". Technicians formulate a backout plan (contingency steps to revert the system) and take a full backup immediately prior to implementation.

4
Validation & Recovery

Following execution, the system owner validates that all services run as expected. If failures occur, the rollback plan is initiated to restore the stable baseline state.

IV

Deception Technologies

Security teams deploy simulated assets to distract, slow down, and analyze malicious actors, while triggering high-fidelity alerts on unauthorized access.

Honeypots

Decoy systems designed to look like production servers, which attract and isolate attackers to study their techniques.

Honeynets

A complete mock network infrastructure consisting of virtualized firewalls, routers, and decoy servers to study network attacks.

Honeyfiles

Attractive, decoy files (such as "passwords.txt") that trigger immediate silent alerts the moment they are opened or accessed.

Honeytokens

Traceable, fake pieces of data (e.g., mock email addresses, database rows, API credentials) used to identify data leaks and track distribution.

V

The CIA Triad & Gap Analysis

The foundational framework of information security consists of three core components, often evaluated against target standards using gap analysis models:

🕵️ Confidentiality

Ensuring that only authorized users can access sensitive data (achieved via encryption, masking, access control lists).

🛡️ Integrity

Ensuring that data remains complete, accurate, and unaltered (achieved via hashing, digital signatures, version controls).

🔋 Availability

Ensuring systems and data are accessible when needed (achieved via fault tolerance, redundancy, backups, and patching).

Gap Analysis Reports

A gap analysis compares an organization's current security posture against a desired standard or baseline (such as NIST SP 800-171 or ISO 27001). The resulting report details the current status, the target baseline, and outlines a specific roadmap of time, budget, and resources to close the gaps, often utilizing color-coded status tables (Red/Yellow/Green).

Detailed Review Quiz

Test your understanding of the concepts in Video 1 to 10. Reveal the answers to check your knowledge.

1. What is the primary difference between identification and authentication in a security system?
Answer: Identification occurs when a user claims a specific identity on a system, typically by providing a username. Authentication is the subsequent process of proving that claim is true by providing secrets like passwords or additional authentication factors.
2. How does a centralized AAA server facilitate the login process for remote access, such as a VPN?
Answer: The AAA server acts as a central database for credentials that individual devices like VPN concentrators do not store. When a user attempts to log in, the concentrator passes the request to the AAA server, which verifies the credentials against its database and sends an approval or denial back to the device.
3. Why is using an "abstraction" or authorization model considered superior to manually assigning rights and permissions?
Answer: Manually assigning permissions to individual users does not scale well as organizations grow to hundreds or thousands of employees. By using an authorization model to group users (e.g., a "Shipping" group), administrators can assign rights to the group once, automatically granting those permissions to any user added to that group.
4. What specific factors must a change control board consider when analyzing the risk of a proposed system update?
Answer: The board must weigh the risk of making the change, such as potential system instability or data corruption, against the risk of not making the change, such as leaving a security vulnerability unpatched. They also consider the timing of the change, ensuring it does not occur during critical business periods like a retail "freeze" between Thanksgiving and New Year’s.
5. In the context of change management, what is a "backout plan" and why is it necessary?
Answer: A backout plan is a documented series of steps designed to revert a system to its original configuration if a change fails or causes unforeseen problems. It is necessary because some changes are difficult to uninstall, and having a plan—and a full backup—ensures the network can be restored to a known good state.
6. How do honeyfiles and honeytokens assist security professionals in detecting unauthorized activity?
Answer: Honeyfiles are fake documents (like "passwords.txt") that trigger alerts when accessed, indicating an intruder is present. Honeytokens are traceable pieces of fake data, such as fake email addresses or API credentials, that allow security teams to see where stolen data is being distributed on the internet.
7. What are the primary components of a gap analysis report, and how are they used to prioritize security improvements?
Answer: The report compares the current security state to a desired baseline (like NIST or ISO standards) and outlines a pathway forward involving time, money, and equipment. It often uses color-coded tables (Red, Yellow, Green) to show which locations or requirements need the most urgent attention to meet the baseline.
8. Distinguish between technical controls and operational controls, providing an example of each.
Answer: Technical controls are implemented through systems and software, such as firewall rules or antivirus programs. Operational controls are implemented through human processes and people, such as hiring security guards or conducting monthly "lunch and learn" awareness programs.
9. How does a digital signature provide both proof of integrity and proof of origin?
Answer: A digital signature involves encrypting a hash of the message with the sender's private key; the hash ensures the message content hasn't changed (integrity), while the private key confirms the sender (origin). This creates non-repudiation, as the sender cannot deny their involvement since only they possess the private key required to create that specific signature.
10. Explain the role of fault tolerance and patching in maintaining the "Availability" leg of the CIA Triad.
Answer: Availability ensures systems remain accessible to authorized users at all times. Fault tolerance achieves this by using redundant components that can take over if one fails, while regular patching ensures systems are stable and protected against exploits that could cause downtime.

I

Cryptographic Foundations: Hashing & Digital Signatures

Hashing

A cryptographic hash is a "digital fingerprint" or message digest that represents data as a short, fixed-length string of text. Hashing is a one-way process; the original data cannot be recreated from the hash.

Core Purpose
Integrity

Verifies that data has not been altered. Even a single character change (e.g., changing a period to an exclamation mark) results in a drastically different hash (the avalanche effect).

Popular Algorithms
SHA-256 vs MD5
  • SHA256: Produces 256 bits of information, represented as 64 hexadecimal characters. Common standard.
  • MD5: Older algorithm, no longer recommended due to collisions (vulnerabilities where different inputs yield matching hashes).
Practical Applications
File Verification

Comparing a downloaded file's hash to the one posted on the source website to confirm it was not tampered with.

Password Storage

Storing password hashes instead of plaintext in databases. A compromised database does not reveal original passwords directly.

Salting

Adding unique, random data to a password before hashing to neutralize rainbow table attacks (pre-compiled hash lists).

Digital Signatures

Digital signatures provide three key security benefits: Authentication, Non-repudiation, and Integrity.

How It Works (Process Flow)
  1. The sender hashes the plaintext document.
  2. The sender encrypts this hash using their own private key. This encrypted hash is the digital signature.
  3. The receiver decrypts the signature using the sender's public key to retrieve the hash.
  4. The receiver calculates a local hash of the received document and compares it to the decrypted hash.
  5. If the hashes match, the document's authenticity and integrity are verified, and the sender cannot deny sending it.
II

Encryption Technologies & Key Management

Encryption States
Data at Rest

Protected using full disk encryption like BitLocker (Windows) or FileVault (macOS), or file-level encryption like EFS (Windows).

Data in Transit

Secured using HTTPS (SSL/TLS) for web traffic or VPNs. Site-to-site VPNs often use IPsec, while client-based VPNs use SSL/TLS.

Database Encryption
  • Transparent Encryption: Uses a symmetric key to encrypt the entire database file on disk.
  • Column-level Encryption: Encrypts specific sensitive fields (e.g., SSN, credit cards) to minimize processing overhead.
Algorithms & Keys

Encryption relies on public, well-known algorithms (like AES or DES), while security is maintained strictly through the secrecy of the key.

Symmetric vs Asymmetric
  • Symmetric: Single shared key for both encryption and decryption. Fast, but hard to distribute securely at scale.
  • Asymmetric: Public/private key pair. Public key encrypts, private key decrypts. Scales easily, but slower.
Key Exchange Methods
  • Out-of-band: Exchanging keys via an external, non-network medium (e.g., phone, courier).
  • In-band: Exchanging keys over the network, using asymmetric encryption to protect a session key.
  • Key Exchange Algorithms: Dynamically building matching symmetric keys on both sides without sending the key itself.
Key Stretching

Hashing or encrypting a key multiple times (e.g., PBKDF2 or bcrypt) to slow down brute-force attacks.

III

Public Key Infrastructure (PKI) & Certificates

PKI encompasses the policies, hardware, software, and procedures used to manage, distribute, and revoke digital certificates.

Digital Certificates
  • Standard Format: X.509 is the global standard format for digital certificates.
  • Certificate Authority (CA): A trusted third party that validates identities and cryptographically signs certificates.
  • CSR (Certificate Signing Request): The initial file created by an applicant (containing their public key and identification details) sent to a CA to request a signed certificate.
  • Wildcard Certificates: Uses an asterisk (e.g., *.domain.com) to secure a main domain and all its subdomains.
Trust Models & Revocation
  • Root of Trust: An inherently trusted anchor (software, hardware, or firmware) used to validate other elements in the trust chain.
  • Web of Trust: An alternative decentralized model where individuals sign each other's certificates.
  • CRL (Certificate Revocation List): A list of revoked certificates maintained by the CA. Browsers download this file periodically.
  • OCSP (Online Certificate Status Protocol): A real-time protocol allowing browsers to query the CA about a single certificate's status.
  • OCSP Stapling: The web server "staples" a time-stamped, CA-signed OCSP response directly into the SSL handshake, reducing traffic to the CA.
IV

Cryptographic Hardware

Hardware Type Core Function Key Use Case
TPM (Trusted Platform Module) A dedicated security chip embedded on a motherboard providing local cryptographic operations. Full-disk encryption (e.g., Windows BitLocker), secure boot validations, and secure local key storage.
HSM (Hardware Security Module) A high-performance physical device or plug-in card for large-scale enterprise cryptography. Managing, storing, and generating keys for thousands of SSL web servers in an enterprise datacenter; offers high-availability.
Secure Enclave A dedicated co-processor built directly into modern CPU architectures, isolated from the main processor. Managing the device boot ROM, real-time memory encryption, and hardware-based AES on mobile devices (e.g. Apple FaceID/TouchID).
V

Obfuscation & Data Privacy

Concealed Writing
Steganography

Hiding data within another medium, such as an image, audio, or video file. The data is hidden in plain sight, relying on "security through obscurity."

Data Replacement
Tokenization

Replacing sensitive data (e.g., credit card numbers) with a non-mathematical random "token". Highly used in secure mobile payments (Apple Pay / Google Pay).

Visual Redacting
Data Masking

Hiding parts of a data string visually (e.g., masking the first twelve digits of a credit card with asterisks: **** **** **** 1234 on a customer receipt).

VI

Technical Change Management

Effective IT operations require structured, documented processes for technical modifications to preserve system stability and security posture.

Change Control Scope

Technicians must strictly adhere to the documented scope approved by a change control board. Unapproved deviations can destabilize systems.

Downtime Management

Changes are scheduled for off-peak/non-production hours. High-availability systems use clustering or secondary environments to swap traffic seamlessly during updates.

Dependencies & Rollbacks

Modifications must map secondary services (e.g. updating a firewall's rules before updating applications). Version control of configurations allows easy reversals if issues arise.

Legacy Systems

Older, unsupported systems that are poorly understood but critical to operations require special isolation and protection controls during change windows.

What is a "collision" in hashing, and why is it problematic?
Answer: A collision occurs when two different data inputs result in the exact same hash output. This is problematic because it undermines the integrity of the hash, allowing an attacker to substitute a malicious file for a legitimate one without detection.
How does "salting" improve the security of password storage?
Answer: Salting adds unique, random data to a password before it is hashed. This ensures that even if two users have the same password, their stored hashes will be different, effectively neutralizing the effectiveness of pre-compiled rainbow tables.
Explain the primary difference between a Certificate Revocation List (CRL) and the Online Certificate Status Protocol (OCSP).
Answer: A CRL is a large file listing all revoked certificates that a browser must download and search manually, which is inefficient. OCSP is a protocol that allows a browser to query a CA in real-time about the status of a specific certificate, making the process much faster.
What is the purpose of a Certificate Signing Request (CSR) in the PKI process?
Answer: A CSR is a file created by an organization that includes its public key and identifying information. It is sent to a Certificate Authority, which validates the information and signs the certificate using its private key.
How does a Hardware Security Module (HSM) differ from a Trusted Platform Module (TPM)?
Answer: A TPM is a chip built into a single device's motherboard to provide localized cryptographic services like BitLocker. An HSM is a centralized, high-performance hardware device designed to manage and protect encryption keys for thousands of devices in a data center.
Describe the process of "steganography" and its relationship to security.
Answer: Steganography is the practice of hiding data inside another medium, such as an image, audio, or video file. It is considered "security through obscurity" because the data is visible to anyone who knows how to look for it, but otherwise remains hidden in plain sight.
How does tokenization protect credit card information during a transaction at a retail store?
Answer: In retail, the actual credit card number is replaced by a one-time-use random token. Because the token has no mathematical relationship to the original card number and expires after one use, it is useless to an attacker if captured.
What role does a "Secure Enclave" play in modern mobile devices?
Answer: The Secure Enclave is a dedicated security processor with its own boot ROM and random number generator. It handles real-time encryption of data in memory and manages cryptographic keys that cannot be accessed by the main CPU.
Why is it important for a technician to adhere to the "documented scope" during a change control window?
Answer: Adhering to the documented scope ensures that only approved changes are made, preventing unintended consequences or system instability. If a technician makes unauthorized changes during a window, it complicates the troubleshooting process if a failure occurs.
Define an "Advanced Persistent Threat" (APT) and identify which threat actor is most likely to use one.
Answer: An Advanced Persistent Threat is a sophisticated, long-term attack aimed at high-value targets like utilities or military systems. These are typically utilized by nation-state threat actors who have the massive financial and technical resources required to sustain such operations.
